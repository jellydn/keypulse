## Codebase Patterns
- SwiftPM-based macOS app project structure
- Build with: `cd KeyPulse && xcodebuild -scheme KeyPulse -destination 'platform=macOS' build`
- Alternative build: `cd KeyPulse && swift build`
- LSUIElement apps use `NSStatusBar.system` (not `.shared`)
- Import AppKit + Carbon for macOS menu bar apps
- SwiftPM `.process()` flattens resource directory structure - use unique filenames across all resources
- Use `Bundle.module.url(forResource:withExtension:)` to access SwiftPM bundled resources
- CGEventTap is preferred over IOHIDManager for global keyboard monitoring (simpler API, no device enumeration)
- Use `kCGEventTapOptionListenOnly` for passive monitoring without intercepting events
- Accessibility permission check: `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: false])`
- Pass `self` to C callbacks via `Unmanaged.passUnretained(self).toOpaque()` and convert back with `fromOpaque().takeUnretainedValue()`
- KeyPulseController acts as the central coordinator between KeyboardMonitor and AudioEngine
- Random sample selection for variety: `Int.random(in: 0..<SoundAssets.samplesPerProfile)`
- KeyPulseController must be retained by AppDelegate to prevent deallocation
- Always check accessibility permission before starting keyboard monitoring
- AudioEngine.volume uses didSet observer for automatic clamping (0.0-1.0 range)
- AudioEngine.isMuted short-circuits playback at the start of play() method (no buffer scheduling when muted)
- KeyPulseController.setVolume(_ percent: Int) converts percentage (0-100) to Float for AudioEngine
- Update volume on all player nodes via loop in updateVolume() method
- SettingsStore uses UserDefaults with `object(forKey:)` check to distinguish unset values from valid values (e.g., volume=0 vs not set)
- SettingsStore is a singleton for app-wide access; settings saved immediately on change via menu callbacks
- Use `applicationWillTerminate` to ensure settings are saved before app quit
- Pitch randomization uses AVAudioPlayerNode.rate property (±5% via Float.random(in: 0.95...1.05)) - simpler than AVAudioUnitTimePitch
- SettingsStore stores Bool settings with same `object(forKey:)` pattern as other types to distinguish unset from false
- SMAppService.mainApp provides launch-at-login on macOS 13+; status property is source of truth
- ServiceManagement framework required in Package.swift linkerSettings
- Launch at Login UI uses same pattern as other toggles; checkmark reflects SMAppService status
- App maintains LSUIElement = YES (no Dock icon) for set-and-forget experience
- **Sound Assets**: Procedurally generated CC0 WAV files, distinct per profile (Linear: 180Hz thock, Tactile: 280Hz bump, Clicky: 450Hz + 3.5kHz click)
- **Latency Measurement**: Use `CACurrentMediaTime()` from QuartzCore for high-precision timing (mach absolute time)
- **Latency Pattern**: Capture trigger time at start of method, record measurement at end using `recordLatencyMeasurement(triggerTime:)`
- **Latency Stats**: AudioEngine provides `averageLatency`, `maxLatency`, `minLatency`, `latencyReport()` for performance monitoring
- **Pre-loaded buffers**: Use `AVAudioPCMBuffer` loaded at startup to eliminate file I/O during playback (<20ms target)
- **Round-robin players**: Multiple `AVAudioPlayerNode` instances enable concurrent playback without cutting off sounds
- **Debug Window**: SwiftUI-based floating window (360x420) with NSHostingController, updates throttled to 10Hz via Combine `.throttle(for: .milliseconds(100), scheduler: DispatchQueue.main, latest: true)`
- **Diagnostics**: KeyPulseController is ObservableObject with @Published diagnosticsData for real-time UI binding
- **Test Sound**: Controller.testPlay() and testAllProfiles() methods for Debug Window verification
- **Modifier Flags**: CGEventFlags.contains(.maskShift/.maskCommand/.maskAlternate/.maskControl) for live modifier state display

- **Learnings for future iterations:**
  - SettingsStore as ObservableObject: Use `objectWillChange.send()` in setters (not @Published on computed properties), as computed properties can't use @Published directly
  - Use `@ObservedObject` (not `@StateObject`) for singleton stores in SwiftUI views, since the instance already exists
  - Preferences window at `.titled + .closable` style mask (non-resizable), following standard macOS preferences window conventions
  - Use NotificationCenter for cross-component actions (e.g., "Show Debug Window" from Advanced tab)
  - Preferences changes propagate to menu bar via `onSettingsChanged` callback → `menuBarManager.refresh()` pattern
  - Menu bar changes propagate to Preferences automatically because SettingsStore is ObservableObject with @ObservedObject binding
  - Preferences window uses NSWindow.frame autosave name `keypulse.preferences` for position persistence
  - `windowShouldClose` returns false and calls `orderOut` to hide instead of close (reuse window instance)
  - `NSApp.activate(ignoringOtherApps: true)` required to bring window to front from background menu-bar app
  - Setting UserDefaults from SwiftUI bindings works correctly because PreferencesView uses Binding(get/set) that writes to SettingsStore
  - All 135 tests pass, build succeeds with no warnings
