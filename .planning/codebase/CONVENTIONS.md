# Coding Conventions

**Analysis Date:** 2026-05-02

## Naming Patterns

**Files:**
- PascalCase for Swift source files, matching the primary type they define
- Examples: `KeyPulse.swift`, `AudioEngine.swift`, `KeyboardMonitor.swift`, `MenuBarManager.swift`, `SettingsStore.swift`, `SoundAssets.swift`, `KeyPulseController.swift`, `KeyPulseAppDelegate.swift`
- One primary type per file (type_FILENAME pattern not used; filename = type name)

**Functions:**
- camelCase for all functions and methods
- Verb-first naming: `setupController()`, `applySettingsToController()`, `setupMenuBar()`, `syncMenuState()`
- Boolean getters use `is` prefix: `isRunning`, `isMuted`, `isMonitoring`, `isProfileLoaded()`
- Factory/creation: `createMenuBarIcon()`, `buildMenu()`
- Actions: `toggleEnabled()`, `toggleMute()`, `profileSelected()`
- Callbacks use `on` prefix: `onKeyDown`, `onEnabledChanged`, `onProfileChanged`, `onError`

**Variables:**
- camelCase for all properties and local variables
- Private backing stored properties: `playerNodes`, `buffers`, `nextPlayerIndex`
- Private(set) for read-only-from-outside: `currentProfile`, `isRunning`
- Descriptive names: `concurrentPlayerCount`, `pitchRandomizationRange`, `samplesPerProfile`
- Singletons use `.shared`: `SettingsStore.shared`

**Types:**
- PascalCase for all types (classes, structs, enums, protocols)
- Classes: `AudioEngine`, `KeyboardMonitor`, `MenuBarManager`, `KeyPulseController`, `KeyPulseAppDelegate`, `SettingsStore`
- Enums: `SoundProfile`, `AudioEngineError`
- Nested enums for constants: `SettingsStore.Keys`, `SettingsStore.Defaults`

## Code Style

**Formatting:**
- No external formatting tool configured (no `.swift-format` config or similar)
- Standard Swift indentation (4 spaces)
- Max line length ~120 chars (flexible, not enforced)
- Trailing closures preferred for callbacks

**Linting:**
- No dedicated Swift lint configured
- Swift compiler warnings serve as the primary lint mechanism
- `@discardableResult` used explicitly for optional-return methods

## Import Organization

**Order:**
1. Foundation frameworks: `import Foundation`, `import CoreGraphics`
2. Apple media frameworks: `import AVFoundation`
3. AppKit: `import AppKit`
4. System frameworks: `import Carbon`, `import ServiceManagement`
5. Test module: `@testable import KeyPulse`

**Examples from codebase:**
- `KeyPulse/Sources/KeyPulse/KeyboardMonitor.swift` — `import Foundation`, `import CoreGraphics`, `import Carbon`, `import AppKit`
- `KeyPulse/Sources/KeyPulse/SettingsStore.swift` — `import Foundation`, `import ServiceManagement`
- `KeyPulse/Sources/KeyPulse/AudioEngine.swift` — `import Foundation`, `import AVFoundation`

**Path Aliases:**
- No path aliases; SPM module imports only
- `Bundle.module` used for resource access (auto-generated by SPM)

## Error Handling

**Patterns:**
- Custom error enums conform to `Error`: `AudioEngine.AudioEngineError`
- Throwing initializers: `KeyPulseController.init(initialProfile:) throws`, `AudioEngine.start() throws`
- `try` at call sites with `catch` blocks
- NSError bridging in Core Audio: `AVAudioConverter` errors via `NSError` pointer
- Some errors caught silently with `try?` for optional file loading
- Optional error handler callback: `var onError: ((Error) -> Void)?` on `KeyPulseController`

**Error enum example** (`KeyPulse/Sources/KeyPulse/AudioEngine.swift`):
```swift
enum AudioEngineError: Error {
    case engineNotRunning
    case invalidSampleIndex
    case bufferLoadFailed
    case engineStartFailed
}
```

**Guard-based validation:**
- `guard !isRunning else { return }` — early return for idempotent guards
- `guard !isMuted else { return }` — early return for short-circuit checks
- `guard isRunning else { throw AudioEngineError.engineNotRunning }` — throwing guards

## Logging

**Framework:** `print()` to console (no OSLog or logging framework)

**Patterns:**
- Prefixed messages: `"KeyPulse: "`, `"KeyboardMonitor: "`
- State change logging in `KeyPulseAppDelegate`: `"KeyPulse: Enabled state changed to \(enabled)"`
- Error logging: `"KeyPulse: Failed to initialize controller: \(error)"`
- Lifecycle logging: `"KeyboardMonitor: Started monitoring keyboard events"`

**Locations:**
- `KeyPulse/Sources/KeyPulse/KeyPulseAppDelegate.swift` — 11 `print()` calls
- `KeyPulse/Sources/KeyPulse/KeyboardMonitor.swift` — 4 `print()` calls
- `KeyPulse/Sources/KeyPulse/SettingsStore.swift` — 2 `print()` calls (error only)
- `KeyPulse/Sources/KeyPulse/AudioEngine.swift` — 1 `print()` call (conversion error)

## Comments

**When to Comment:**
- Doc comments (`///`) on all public/internal types and methods
- Implementation notes explaining design trade-offs (e.g., `KeyboardMonitor` CGEventTap vs IOHIDManager)
- `// MARK: -` sections for organizing code within types

**Doc Comments:**
- Triple-slash `///` format on all public APIs
- Parameter docs: `- Parameter profile: The sound profile to load.`
- Return docs: `- Returns: True if accessibility is enabled for this app.`
- Throws docs: `- Throws: AudioEngineError if the engine fails to start.`
- No `/** */` block comments used

**MARK Sections (from codebase):**
- `// MARK: - Lifecycle` — init/deinit (`AudioEngine`)
- `// MARK: - Profile Loading` — profile methods (`AudioEngine`)
- `// MARK: - Playback` — play methods (`AudioEngine`)
- `// MARK: - Volume Control` — volume methods (`AudioEngine`)
- `// MARK: - Permission Handling` — accessibility checks (`KeyboardMonitor`)
- `// MARK: - Monitoring Control` — start/stop (`KeyboardMonitor`)
- `// MARK: - Event Handling` — CGEvent callback (`KeyboardMonitor`)
- `// MARK: - Setup` — initialization (`MenuBarManager`)
- `// MARK: - State Sync` — UI sync (`MenuBarManager`)
- `// MARK: - Actions` — IBAction methods (`MenuBarManager`)
- `// MARK: - Public API` — public methods (`MenuBarManager`)
- `// MARK: - Private Methods` — private helpers (`KeyPulseController`, `SettingsStore`)

## Function Design

**Size:**
- Functions generally < 40 lines; delegation methods can be longer
- Long methods exist primarily in `MenuBarManager.buildMenu()` for UI construction

**Parameters:**
- Named parameters with labels: `loadProfile(_ profile:)`, `play(sampleIndex:)`, `setVolume(_ percent:)`
- Default values used sparingly: `init(initialProfile: SoundProfile = .linear)`

**Return Values:**
- `Bool` for status: `start() -> Bool`, `checkAccessibilityPermission() -> Bool`
- `throws` for failure cases
- Computed properties for derived values: `volume: Int`, `isMuted: Bool`
- `@discardableResult` on `start()` in `KeyPulseController`

## Module Design

**Exports:**
- One primary type per file
- No barrel file or `export` pattern; each type is its own module citizen
- `SoundProfile` and `SoundAssets` are separate types in one file (`SoundAssets.swift`)

**Access Control:**
- Default access: `internal` (Swift default, no explicit keyword)
- `private` on implementation details: player nodes, buffers, internal state
- `private(set)` for publicly readable but privately writable: `currentProfile`, `isRunning`
- `static` for singleton: `SettingsStore.shared`
- `static` for utility methods: `KeyboardMonitor.checkAccessibilityPermission()`, `SoundAssets.sampleURLs(for:)`
- `final class` used on `AudioEngine` and `KeyPulseController` to prevent subclassing

**Memory Management:**
- `[weak self]` in all closures that reference `self` (delegates, callbacks)
- `guard let self = self` used after `[weak self]` capture
- Example from `KeyPulse/Sources/KeyPulse/KeyboardMonitor.swift`:
  ```swift
  DispatchQueue.main.async { [weak self] in
      self?.onKeyDown?(keyCode)
  }
  ```
- Example from `KeyPulse/Sources/KeyPulse/KeyPulseController.swift`:
  ```swift
  keyboardMonitor.onKeyDown = { [weak self] keyCode in
      guard let self = self, self.isEnabled else { return }
  }
  ```
- `deinit` cleans up resources: `AudioEngine.stop()`, `KeyboardMonitor.stop()`
